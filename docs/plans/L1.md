# L1: Is the finished act agent correct over a long run, and how far does it get?

Status: not started · Branch: feat/lean-agent · Program: [program-r1-wm.md](program-r1-wm.md) row 9 (STOP 4 after: program done)

## Why this phase exists (user decision 2026-10-12, build-first)

Every live failure so far was a correctness bug (exit nomination, place identity, player/NPC swap), found expensively through a performance gate and then diagnosed offline anyway. L1 judges the finished system in two layers:
1. **Health:** is what the agent believes true, checked against RAM truth.
2. **Progress:** how far does it get?

Health is read first. Progress is reported, not gated.

## 1. Entry criteria
- P3b, P4 and W4 gates passed (act is the only path, motion anchors are in).
- On disk: the ROM, `.cache/model/`, `runs/m1_act` (P3 evidence, read only). Ledger: M1 bucket ≥ 220 left (411 on 2026-10-12). Ollama reachable.

## 2. Gate

**Health table (computed by `scripts/eval_run.py`, 0 requests):**

| Check | Field | Green |
|---|---|---|
| Player identity vs truth sprite slot 0 | `player_role_errors` | 0 |
| A scene cut changes place | `cut_self_loops` | 0 |
| One place id per truth map (world screens) | `place_ids_per_map` | 1 for every map |
| Dialogue/menu screens stored as places | `screen_places` (new) | reported; green = 0 created during the run |
| Seen cells inside the truth map | `seen_in_bounds` | ≥ 98% |
| Tile position vs RAM | tile accuracy (existing) | ≥ 95% |
| Actions with an effect | `no_effect_streak_max` (new): longest run of steps whose outcome is `no_change` | ≤ 5 |
| Same action repeated | `repeat_actions` max length | ≤ 5 |

**Progress (reported only):** truth maps reached and the step each was first reached; party size; new `game_text` rows; notebook goals with quoted evidence; `go_to` travel started/arrived; requests per step.

- **Pass:** the run completes, or exits 3 at the cap with a checkpoint, and the health table is computed. Green or red, the result goes to the user at STOP 4.
- **Early stop (saves requests):** the run is two halves. If any health row other than `screen_places` is red after the first half, do not run the second half. Report.
- **Exit 4, crash, or the model unavailable:** checkpoint, report, stop.
