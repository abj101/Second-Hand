### P3.0: view hygiene (added 2026-10-12 after reviewing the W3 view)
- **Why:** the W3 checkpoint-94 view spent its whole budget listing 17 `shelf#N` records in 1F and four `path east/north/south/west` stubs (model-created `kind: affordance` records with no tile, step 0), so Pallet Town got no lines. P3 resumes from checkpoint 74, whose memory has 56 shelf records in 1F and 9 affordance stubs, so the live model would see the same noise.
- **Change (render only; no memory rows rewritten, no dedupe of stored data):**
  - In "Things here" and under other places, things with the same base name (`memory._base`) in the same place render as one line: `shelf ×17 remembered (nearest (x,y))`; the line keeps the best status among them.
  - Records with `src == "model"`, no tile and never seen on screen (`seen == 0`, e.g. affordance stubs) are not rendered as things.
  - Every live place gets at least its heading and exits before any place's thing lines are filled (two passes within `VIEW_TOKENS`).
- **Acceptance:** unit tests for grouping, stub suppression and "every place has its heading and exits"; `scripts/check_world.py view` on the checkpoint-94 copy shows a `Place: world [p_world]` heading with its exits and at most one `shelf` line per place; the same check on a copy of `runs/m1/checkpoint/000074/memory` stays ≤ 2,000 characters; full `pytest tests/agent -q` green (regenerate a golden only if it records the view, and review the diff).

### P3.1
- `truth_pokered`: add map height/width (`wCurMapHeight`, `wCurMapWidth`; verify addresses against the pokered symbol file; values are in 2×2-tile blocks, so tiles = ×2). Evaluation only.
- `eval_run` new fields, all computed from `trace.jsonl`, `truth.jsonl`, `memory/` and `notebook.json`:
  - `place_ids_per_map`: per truth map, the set of non-merged place ids seen on world steps;
  - `seen_in_bounds`: seen cells shifted by each place's per-visit offset (the existing tile-accuracy offset) and inside `[0, 2·map_w) × [0, 2·map_h)`;
  - `stuck_streak_max`: longest run of steps in one truth map with no new `game_text` knowledge row;
  - `travel`: count of steps whose skill reason starts with `travel` or whose choice was a memory/place `go_to`, and how many arrived at the planned place;
  - `notebook_goals_with_evidence`;
  - `repeat_actions` (same verb + target ≥ 3 in a row) and `reentries` (back into a truth map within 5 steps of leaving it), each with step lists.
- Fields that need data a run doesn't have return null. No baseline numbers are hard-coded.
- **Acceptance:** `pytest tests/agent/test_eval_run.py -q`; `eval_run.py runs/m1` still exits 0 with all earlier fields unchanged.
