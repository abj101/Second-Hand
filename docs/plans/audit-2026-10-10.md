**E2 is ready to execute once five fixes are made (listed below).** E3 is **not ready**. Both have to be fixed in `contracts.md` before E3 is pasted, because an E3 orchestrator is not allowed to edit contracts and would have to stop.

## Top 5 changes before pasting E2

1. **Put the ROM on disk and commit E1.** `Rom/` does not exist at the moment. Copy the ROM in. Then commit the E1 baseline: `agent/`, `tests/agent/`, `scripts/e1_perceive.py`, `CLAUDE.md`, `.gitignore` and `docs/` are all untracked or modified. If this isn't done, E2's commit sweeps in part of E1 (`model.py`, `perceive.py`) and leaves the rest untracked. (B1, M11)
2. **Fix the `scroll()` contract and how it is computed.** Make the contract return `tuple[int, int] | None`, where `None` means unsure. In E2.2:
   - drop "prefer the smallest shift";
   - measure the shift between consecutive frames as the move happens (each frame moves only a few pixels) and add the shifts up, or else search only along the pressed axis.

   In E2.4, an unsure result (`None`) must not be read as `blocked`. (B2)
3. **Change the settle rule in E2.2.** Count a frame as quiet when it matches a frame already seen in the window (compare frame hashes). Animated tiles cycle through the same frames; text printing and fades do not.
   - Never settle on a uniform (blank) frame.
   - Make `quiet` at least the press length (about 24 frames). Emulator frames cost nothing.
   - Add the optional field `Settle.blank_seen` and feed it into `cut()`. (M1)
4. **Give E2.5 concrete truth.**
   - `screen_text` decoded from `wTileMap` (0xC3A0, 20×18 tiles) with the Gen 1 charmap: A–Z = 0x80–0x99, a–z = 0xA0–0xB9, space 0x7F, terminator 0x50.
   - `text_box` = box-border tiles 0x79–0x7E present in rows 12–17.
   - Sprite truth from `wSpriteStateData1` (0xC100, 16 slots, slot 0 = the player).
   - The menu goal succeeds when `"TEXT SPEED"` appears in `screen_text`.
   - Check each value against `pokered.sym`. (M10, m20)
5. **Make every command runnable as written.**
   - Use `.venv-agent/Scripts/python.exe`. It works in both PowerShell and Git Bash; backslash paths break in Bash.
   - Tests import `from tests.agent.fakes import GridEnv, StubModel`, because `pyproject.toml` sets `--import-mode=importlib`.
   - Each WP's acceptance runs only its own test files. The orchestrator runs the full suite after each parallel batch.
   - Add the PyBoy gotchas to the E2.1 card (see m3). (M9, m13, m3)

**Before pasting E3**, apply M2–M7 and M12–M13 to `contracts.md` and `E3.md`.

## Answers to the audit questions

1. **Does the loop close?**
   - **Mechanically, not yet.** Steps 3, 5 and 10 of E3.5 need the glue in M4, and step 1 needs M1. Resume needs M5.
   - **Place identity, as specified, does not work for Pokémon** (M2, M3). Continuity plus edges fixes it at lower cost than landmark matching.
   - **Code-only verification is enough** for the effects that matter for M1 and E4: scroll, cut and place change, once M1 and M6 are fixed. It is not enough for effects that come only from text or entities.
2. **Contracts.**
   - Mismatches: `match_place` has no ctx or cut parameter (C:260 vs E3.md:99); `checkpoint/` is singular while E3 resumes at step K (C:355); `choose` has no game parameter (C:334 vs E3.4).
   - Missing fields: `Choice.text`, the `view` ctx keys, the predicate vocabulary, `scroll`'s `None`.
   - Unowned: affordance-to-id resolution, resume truncation, the replay test.
   - No file is owned by two WPs. E4.2 and E4.3 meet at an import (m7).
3. **Pokémon and PyBoy risks.**
   - Turning versus moving, and overshoot (m4).
   - Text and fade settling (M1).
   - Animated tiles (M1c).
   - Repeating-tile registration (B2).
   - Naming keyboard: covered by the read-back check and the "a preset counts" rule; the rival has a "BLUE" preset.
   - Menus: fine with `select`.
   - Warps (M1b, m5).
   - The RAM addresses in E2.5 match the pokered symbols: `wCurMap` D35E, `wYCoord` D361, `wXCoord` D362, `wPartyCount` D163, `wIsInBattle` D057, `wPlayerName` D158, `wRivalName` D34A, and map ids 0x00, 0x25, 0x26, 0x28. They are still to be confirmed empirically, as the plan says.
   - OAM truth: see m20.
4. **Tech stack.**
   - **PyBoy 2.x:** the API is as the plan lists it, plus the gotchas in m3. Wheels exist for cp312 on Windows.
   - **Registration:** numpy FFT is not needed. A brute-force search over small shifts is shorter and avoids the periodic ambiguity (B2).
   - **JSONL stores and the stdlib cache:** fine, with m11.
   - **decider-2b:** low value for the cost (m15).
   - **Ollama free tier:** the limits run over usage windows, not per minute (m12).
   - **`uv` and `.venv-agent`:** fine (uv 0.10.10, Python 3.12.13; the five E1 tests pass).
   - **Dependencies:** nothing is missing besides `pyboy`, and nothing unneeded is added. `windows-capture` is correctly deferred to E5.
5. **Plan quality.**
   - Tiers are realistic. The exceptions: E3.5 (90 lines) can't absorb the M4 glue, and E2.5's input script through the intro is the biggest time sink.
   - Commands: see M9.
   - Parallel safety: fine apart from m7 and m13.
   - Gates: measurable apart from E2's stuck-keys row (m18), E2's menu and text truth (M10), and E4's learning gate (M8).
   - Caps: E2's cap of 60 is fine. E3 and E4 are short (M7, m6).
   - Handoff notes: enough, since contract proposals travel in the Result sections. But E2's decision 1 ("if registration isn't trusted, E3 re-perceives every N steps") has no branch in E3.md.

## Over-engineering to cut (ponytail)

- **`ReplayEnv` (E2.1).** No WP uses it, and the response cache plus PyBoy's determinism already make replays free.
- **FFT phase correlation.** Replace it with the small brute-force shift search. That is fewer lines, uses no FFT, and fixes B2.
- **`scripts/check_pokemon_perception.py` (80 lines).** Fold it into `run_goal`'s summary (about 20 lines).
- **E4 `--compare`.** It is built now for a run that is deferred. Build it when the ablation is scheduled.
- **Shortcuts in E4 (about 110 lines).** A curiosity run rarely repeats the same route three times identically, so `shortcut_unsafe = 0` passes without testing anything. Defer them, or make the row report-only (see the questions).
- **`Memory.compact()` and `route()` in E3.** The stores stay tiny at 1,000 steps, and nothing in the E3 loop calls `route`.
- **The copy-and-trim instructions for `profile.py` and `gateway.py`.** There is nothing to reuse (m1, m2).
- **Brief format fields** beyond controls, notes and defaults (n3).

## Missing essentials (ponytail never cuts these)

- **Settling:** never settle on a blank or fading frame, and don't stop while text is still printing (M1).
- **Scroll:** keep "unsure" separate from "no scroll" (B2).
- **Places:** place continuity, and the screen-versus-place distinction (M2, M3).
- **Resume:** step-numbered checkpoints, truncating rows after the resume step, and checkpointing harness state (M5).
- **Basis on effects:** each effect is marked pixel or model, so that model output never becomes `observed` (M6).
- **Owned glue:** affordance-to-id resolution, the predicate table, the view ctx, and the text to type (M4).
- **Zero-affordance fallback** (m14), and **a distinct exit code when the cloud is unavailable** (m12).
