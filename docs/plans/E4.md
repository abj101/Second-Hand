| **Memory matters (offline proxy, 0 calls):** the same trace re-predicted with memory hidden (no instance or pattern basis) | full ≥ hidden + 0.05 | `eval_run.py runs/e4 --repredict --hide-memory` |
| Repeated mistakes, retrieval use, poison rate, cost per step | report only | `summary.json` |

The audit showed that comparing first and last thirds of the run is too noisy at 300 steps. Repeat against first encounters measures learning directly.

- **Decisions this gate produces:**
  1. The tuned pattern thresholds (spec §8: "tune on the first E4 run"). Tune offline with `--repredict`.
  2. Memory items never used (retrieval use near 0). Prune them from `view`.
  3. Whether shortcuts are worth building yet: from the repeat-sequence counts that `eval_run` reports.
- **If it fails:**
  - **Learning flat:** check whether predictions ever use `basis = pattern`. If patterns never promote, inspect the instance keys. The root-cause fix is kind normalization in `memory.py`, not lower thresholds.
  - **No battle:** check the trace for battle screens (candidate places). If moves were never `select`ed, it is a skill or dispatch issue.
  - Report to the user before any extra run.

### E4.1: Patterns

- **Goal:** generalize verified relations into counted patterns. Code promotes; models never do.
- **Create or change:**
  - `agent/memory.py`:
    - On every `relate(..., hit=True)` that is `observed` (pixel basis), update the pattern keyed `(kind(s), p, kind(o), verb)`.
    - **Support** is the number of distinct instances with a verified hit.
    - **Candidate** at support ≥ 2. **Promoted** at support ≥ 3 with contradictions ≤ 10%. **Demoted** if 2 of its last 5 uses missed. Keep the thresholds in one `THRESHOLDS` dict.
    - **Kind normalization:** casefold; singularize a trailing "s"; a small alias map, which must be game-neutral (e.g. "doorway" → "door"). Flag any Pokémon-specific alias in the Result section.
    - The orchestrator view lists the candidate patterns with their counts.
  - `agent/predict.py`: when no instance matches, use a promoted pattern for the target's kind and verb, with `basis = "pattern"`.
- **Tests:**
  - three door instances give candidate, then promoted;
  - two misses in the last five demote it;
  - model-basis facts never count toward support;
  - the pattern fallback is used only when no instance matches;
  - "doors" and "Door" merge.
- **Acceptance:** `.venv-agent/Scripts/python.exe -m pytest tests/agent/test_patterns.py -q`
- **Done when:** the tests are green, the budgets hold, and `reflect` can set only a pattern's `name`.

### E4.2: Reflection and wake

- **Create or change:**
  - `agent/decide.py`: `reflect(model, view) -> {"tasks", "pattern_names", "notes"}`, with a strict schema and at most 3 tasks.
  - `agent/tasks.py`: `wake(row, step)` fires on a task ending, a new place (state `place`), a surprise verdict, `Stuck`, or every 50 steps.
  - Curiosity stays a **ranking rule** in the Chooser view (untried affordances, unexplored exits, low-confidence relations first), not task records. Subtasks still come only from `escalate` or `reflect`.
- **Tests (`StubModel`):** wake fires on each trigger and on nothing else; a reflection naming an unknown pattern id is ignored; at most 3 tasks are accepted.
- **Acceptance:** `.venv-agent/Scripts/python.exe -m pytest tests/agent/test_reflect.py -q`

### E4.3: Wire reflection into the loop

- **Create or change:** in `agent/loop.py`, after each trace row: `if (reason := tasks.wake(row, step)): apply(reflect(model, mem.view("orchestrator", ctx)))`. Here `apply` adds the returned tasks and sets only pattern names. The reflect call is logged with `role = "reflect"`.
- **Tests:** a GridEnv loop with a stub `wake` that fires once makes exactly one reflect call.
- **Acceptance:** `.venv-agent/Scripts/python.exe -m pytest tests/agent/test_loop.py -q`

### E4.4: Metrics

- **Create or change:** `scripts/eval_run.py`:
  - `doors_verified`, `patterns_promoted`;
  - `battles`, `moves_selected`;
  - `--repredict [--hide-memory]`: rebuilds memory step by step from the trace and re-runs `predict` and `verdict`, offline. It reports `acc_repeat`, `acc_first` and `n`;
  - the repeat-sequence count (for the shortcut decision).
- **Tests:** synthetic run directories with known values for each field; `--hide-memory` lowers accuracy on a run with repeats.
- **Acceptance:** `.venv-agent/Scripts/python.exe -m pytest tests/agent/test_eval_run.py -q`
