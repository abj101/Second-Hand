### R4.7 Live-probe repair (approved 2026-10-11)

The q probe failed at checkpoint 73 (steps 55-73 in `runs/m1/trace.jsonl`). Diagnosis, verified from the trace and the cached perceptions:
- At step 56 the cloud perceiver labelled Mom as the "player" (`[458, 812]` instead of about `[450, 460]`); object coordinates were right. `space.tile_of` projects every entity relative to the perceived player, so all objects landed about 3 tiles off and `observe(tiles=)` created 17 duplicates (`shelf#11`, `stairs#3`, `table#4`, `rug#2`, ...).
- The duplicates made `Memory.resolve(name, place)` ambiguous, so targets got `None` ids. `next_test` keeps candidates with no id, so the stairs (inferred `e_stairs_2 leads_to p_dialogue_screen_4`) passed the tested filter and were taken at step 57.
- Upstairs became a new place `p_world`: checkpoint 54's 2F place has legacy screen `dialogue_screen`, its edge uses `via` `stairs` while the live via was `exit: stairs`, and `match_place` did not consult `leads_to`. That falsely completed "Reach a place not visited yet".
- Live ranker inputs and answers were not logged, so its choices could not be audited.

Fixes (user-approved, `agent/` +19 lines; 3 new tests, 1 extended):
- **A. Stable player anchor (`loop.py`):** a camera-following view keeps the player at a fixed screen spot. `Loop._anchor` keeps up to 9 player samples from `world` screens (first sample until 3 exist, then the median); a sample more than 1.5 tiles from the anchor is not added. All tile projections use the anchor, not each frame's label. Persisted in `state()` / `restore()` as `anchors` (default empty).
- **B. Ambiguous names resolve by tile (`memory.py`, `decide.py`, `loop.py`):** `resolve(name, place, tile=None)` returns the same-name record nearest to `tile` within 1 tile, else the old behaviour; `resolve_target` takes the same kwarg and the loop passes projected tiles (affordance targets, `exit:` entities). Candidates with no id are dropped when within 1 tile of the stored tile of any tested id in this place.
- **C. Re-entry (`memory.py`):** `match_place` compares `via` names without an `exit:` prefix, and before the landmark fallback returns the object of a live `leads_to` relation of `via_id` when that place is known; the loop passes `via_id=targets[choice.i]`.
- **D. Ranker audit (`loop.py`):** the trace row has `"ranker": {"state", "answer"}` for steps where `next_test` asked the judge, else null.
- **Checkpoint 54 re-migration (data):** `screen` set to `world` on `p_dialogue_screen_4` (`p_dialogue_box_2` already was) with `.tmp/e3r4/remigrate_cp54.py`, append-only; backup in `.tmp/e3r4/pre-remigrate/000054/`. Nothing else changed in `runs/m1/`.
- **Budget:** stage q cap 40 -> 60 (+20, user-approved); M1 1,050 and phase 1,100 unchanged, stage c 546, smoke 50.

Replay check (0 calls, `.tmp/e3r4/replay_55_57.py`): the probe's step 55-57 perceptions through anchor, `tile_of` and `observe`. Without the anchor: 15 same-name duplicates (the diagnosis list). With it: 0 projection duplicates; the 4 same-name records left are perceiver output (3 wall windows named `shelf`, and an off-screen `rug` listed). `resolve_target("exit: stairs", tile=...)` gives `e_stairs_2`, and `match_place` for a cut via `exit: stairs` from the 1F returns `p_dialogue_screen_4`.

### R3.2 Design (approved 2026-10-11, after the Sonnet design review)

Gemma sets the goal. Code filters out what memory rules out. decider-2b ranks the remaining candidates, with a code fallback. Code tests them in order and verifies each one by a place change. The Chooser handles only non-navigation choices.

| # | Part | Behaviour | Owner |
|---|---|---|---|
| G1 | **Model-set goals** | **`decide.plan`** (reuses `escalate` and `_TASKS`). The input is `mem.view("orchestrator", ctx)` (3k tokens, all `game_text`), plus the trigger reason, the last goal and how it ended, and the current screen text; no image. The output is ≤ 2 tasks: the main goal, plus an optional child first step (`active()` already prefers the deepest task). Conditions allowed: `new_place` (preferred for "leave" or "go find X"), `text_seen`, `entity_known`, `relation`, `steps_over`. **Guards:** reject a done condition that is already true at creation (`text_seen` scans all `game_text`); every model goal gets `fail_when steps_over` (default 40). **Triggers** (in `loop.py`, not `Tasks.wake`): a goal done or failed (`Tasks.check`'s `changed_tasks`), Stuck, or new `game_text` since the last plan, at most once per 15 steps. No call at step 0; at least 10 steps between calls. About **4–6 calls per 100 steps**. **Fallback default** (no usable model goal): "Reach a place not visited yet", `done_when [{"new_place": true}]`, budget 40, src `default`, re-armed; set to `blocked` while a model goal is active, so it doesn't burn budget or fire Stuck. **`new_place` latches:** store the count of distinct places reached by ok edges (from pixel scene cuts) at task creation; true once that count grows. Never use "place created this step", because landmark drift also creates places. | `agent/decide.py`, `agent/tasks.py`, `agent/loop.py` |
| G2 | **`placement` only** | The Perceiver adds one optional field to each affordance and each entity: `placement`, one of top wall, bottom wall, left wall, right wall, room edge, screen edge, middle. No goal in the Perceiver context, and no `goal_rank`. The review found a goal there would have no effect: the view returns before the task line, and the cache ignores context. | `agent/perceive.py`, `agent/loop.py` |
| G3 | **Memory filter** | A candidate counts as tested if `mem.resolve(target, place)` has any `leads_to` relation (ok or failed). Match on the resolved id, not on `add_edge`'s raw `via` string ("stairs" vs "exit: stairs"). This is a pure function in `decide.py`; `loop.py` computes the tested set. | `agent/decide.py`, `agent/loop.py` |
| G4 | **Test in order** | Runs when the active task's `done_when` has `new_place`, the screen is `world`, and a `player` entity is present. Without a player entity, use the existing `unknown` path. | `agent/decide.py` (`next_test`), `agent/skills.py` (+`exit`), `agent/loop.py` |
| G5 | **Chooser** | Runs for dialogue, menus, naming, text or entity goals, and `world` when no candidate is left. Prompt: `GENERAL` + the brief's controls + `defaults`; the task as goal / progress / budget only; at most 8 knowledge lines, with prefix fragments merged; no all-`None` predictions; known exits and failed tests listed. Keep the `src == "default"` curiosity override. | `agent/decide.py`, `agent/memory.py` (view) |

### E3.1: Memory

- **Goal:** the world model of spec §8, with the audit's identity fixes.
- **Read:** [memory](contracts.md#memory), [trace](contracts.md#trace), and spec §8.
- **Create or change:** `agent/memory.py`, per the contract. **Any store name is accepted.** There is no `route` or `compact` yet.
  - **`match_place(perception, step, *, prev, cut, via)`:**
    - No cut: return `prev`.
    - On a cut: follow the known edge `(prev, via)`; else match on landmark `(name, kind)` overlap ≥ 0.6 against places of the same `screen` type; else create a new **candidate**.
    - A candidate is promoted to `state = "place"` on its first `view_scrolled`.
    - Keep a `screen` label on each place, taken from the perception's `screen`.
  - **Identity:**
    - World things are keyed by `(name, place)`, with `kind` kept as an attribute.
    - Recurring types (`menu_item`, `move`, `item`, `option`) are keyed by `(kind, name)`. Keep that list in one constant.
    - Edit distance ≤ 1 is a match. A tie creates `#2`. Two sightings of one name on one frame are two entities.
  - **`resolve(name, place)`:** finds the entity id for an affordance's target string, using the same name rules.
  - **`view(caller, ctx)`:** ctx is `{"place", "task", "on_screen", "recent", "step"}`.
    - Selection order: on screen or in this place, then tied to the task, then recent, then important.
    - The Chooser view adds the last 5 actions with verdicts, the affordances already failed here, and recent surprises, all from `ctx["recent"]`.
    - The Perceiver view lists the known `name (kind)` entries for the place.
    - Model claims are marked "(unverified)". At most two refuted items appear, under "don't believe".
    - The budget is `len(text) / 4` tokens.
    - It returns the ids it shows.
  - **Facts:** only effects with `basis = "pixel"` add `sup` to `observed` relations. Model-basis effects are recorded with `src = "model"`.
  - **`expire`:** at 200 steps, as in the contract.
- **Tests:**
  - an upsert, restart and replay round trip; an unknown store name works;
  - `match_place`: no cut keeps `prev`; an edge is followed; a landmark match; a new candidate; a candidate promoted on scroll; a battle-like screen stays a candidate;
  - identity: an edit-distance match, kind drift ("mom" npc vs "mom" woman) gives the same id, the `#2` tie, a recurring type across places;
  - `resolve`;
  - `conf` and the refuted rule (`sup = 3` survives one contradiction);
  - model-basis effects never create `observed` facts;
  - expiry;
  - `view` stays under budget, lists its ids, and includes failed affordances from `recent`.
- **Acceptance:** `.venv-agent/Scripts/python.exe -m pytest tests/agent/test_memory.py -q`
- **Done when:** the tests are green, the file is ≤ 280 lines, and there is no database and no embeddings.

### E3.5: Loop and runner

- **Goal:** the spec §5 step, wired end to end, with cheap resume and the fewest calls.
- **Create or change:** `agent/loop.py`, with `Loop(env, model, mem, game)`, `step() -> row`, `state() -> dict` and `restore(dict)`. Each step:
  1. `wait_settled`. **If the settled frame's hash equals the last perceived frame's hash, reuse that perception** (0 calls; bumps into walls are common).
  2. Otherwise `perceive`, with `GENERAL`, the brief, and the Perceiver view built from the **previous** place.
  3. `match_place(prev, cut, via)`, then `observe`, then `know` for each new text line (`src = "game_text"`).
  4. `Tasks.check`.
  5. `resolve` each affordance target, then `predict`.
  6. `choose`, passing `defaults(game)`. Log to `chooser.jsonl` when the model was called. On zero affordances, use `wait_until`.
  7. `run_affordance(..., text=choice.text)`. If registration is untrusted (see the handoff notes), re-perceive every 3 tiles inside `approach`.
  8. `wait_settled` and perceive again. The next step reuses this perception.
  9. `effects` (with basis) and `verdict`.
  10. `relate` through `PRED`, or `add_edge`. Pixel-basis effects become `observed`; model-basis effects become `model`.
  11. Write the trace row.
  12. `Stuck.update`; on a reason, `escalate`.

  `scripts/run_agent.py --game pokemon_red --steps N --max-calls N --run runs/<id> [--resume [--from-step K]]`:
  - builds `PyBoyEnv(find_rom())` and `Ollama(cache_dir=.cache/model)`;
  - passes `truth_pokered.read` as the truth callable;
  - writes `checkpoint/<step:06d>/` every 25 steps, holding the env state, the memory copy and `harness.json` (from `Loop.state()`);
  - on resume, loads the checkpoint and **truncates** the JSONL rows after it;
  - `--steps` means N more steps;
  - exit codes per the contract: 3 at the call cap, 4 on `ModelUnavailable`, and also a clean checkpoint and exit if `env.press` raises.
- **Tests:** `tests/agent/test_loop.py`, on `GridEnv` with `StubModel`:
  - 20 steps produce trace rows with every contract key;
  - an identical frame reuses the perception (0 calls);
  - `chooser.jsonl` is written only for model-made choices;
  - `state()` and `restore()` round-trip;
  - a parse failure doesn't escape;
  - an env that raises on `press` is handled by the runner logic;
  - resume truncation, using a tiny run directory.
- **Acceptance:**
