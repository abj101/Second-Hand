# Audit 2026-10-15: what is actually blocking the agent

Run: `runs/m1_bedroom_live`, 105 steps and 244 model calls (119 perceive, 114 act, 6 plan, 5 skill), model `gemma4:31b-cloud`, decide mode. Steps 1-50 ran on `49a8931`. Steps 50-105 resumed from a checkpoint on `94780b4` (HEAD), and the notebook came along from the checkpoint.

**Bottom line.** Most symptoms come from four mechanisms. The biggest is upstream of planning and acting: **things have no stable identity**. Every "already done / already failed / already talked to" record hangs off an entity or place id, and those ids churn whenever the VLM changes a word. The other three are: quest state that only grows, an act menu that relies on soft rules, and slow or noisy feedback. None of the four needs Pokémon knowledge to fix. Self-location is **not** a problem: 63 of 63 checkable steps were correct.

## Symptoms and their root causes

| Symptom you see | Root causes |
|---|---|
| Repeats mistakes (door/window bumps, re-picking failed exits) | R1, R3, R4 |
| Pointless actions (object tour, 1-tile explore, buttons in dialogue) | R2, R3, R4 |
| Does not follow or prioritise directives ("Oak, next door") | R2, R3 |
| Plans are not concise | R2 |
| Misrecognition (window as door, Mom as "player"/"person") | R5, made fatal by R1 |
| NPC tracking, "already talked to", "already done" | R1, R2 |

## R1. Identity comes from the VLM's free-text name (the main blocker)

- `agent/memory.py:269-271`: a record can match a new observation only if the names are within edit distance 1. Position only breaks ties *among name matches*. `memory.py:297` freezes the name at the first mint. Pixel tracks (OT) override this, but only for actors that keep a live track.
- **Mom:** first `e_character_3`, which correctly got `called=MOM` from the speaker binding (`loop.py:262-266`). Perception then labelled her "player" during dialogue frames and dropped her twice. She was re-minted as `e_person`, losing the binding. At S70 the menu offers "approach person" and "interact with person", with no sign she was already talked to.
- **Wall tiles:** each was minted twice, as "exit: door" and "exit: window". Failure notes are keyed on the entity id (`world.py:22-35`), so the same tile under its other name looks untried. S68's "window" had no note even though S67's "door" on that same tile had just failed.
- **Pallet Town:** 1 NPC got 7 ids. "fence post 3" vs "fence post" is distance 2, and "post" is distance 6, so the posts were re-minted whenever their names changed.
- **Places:** "place N" labels shown to the planner are not names memory knows (`memory.py:35-47`), so quest reach checks can never pass (`notebook.py:399-404`). Place guesses made on dialogue frames ("Professor Oak's lab", "kitchen") became aliases of house 1F (`loop.py:164`). The bedroom has two place ids.
- **Why it is upstream:** the act model is told it does not see the screen. Everything it knows about "what I did to what" goes through these ids, so no history, notes or completion feature downstream can work while ids churn.

## R2. Quest state only grows, and the planner's words don't match its effects

- The planner reply replaces the quest list, but omitting a quest keeps it (`notebook.py:230-236`). A real drop needs status, evidence and, for heard quests, a reference (`212-219`). The planner never sends those. Three times its note says "dropped find_exit_place_2" while the quest stays open, and the act model sees both (S70).
- Nothing closes quests: the reach checks fail (R1), there are no done/dropped ops and no T3 events. By S76 there were 5 open quests: 4 stale `explore_*`/`find_exit` quests plus `meet_prof_oak`.
- The object tour is literal obedience: the top quest at S41-54 was "Investigate the objects in place 2".
- The `_EXPLORE` filter (`notebook.py:15`, added in 1f8118a) was evaded in this same run. The planner wrote "Determine the nature of place 3" instead. A word filter cannot hold against a model that paraphrases.
- **Directive priority** worked mechanically: Mom's line became the top quest. But the quest text dropped "next door", and that meaning reached the act model only through a fact line. Old quests stay listed as "other open quests you may take".
- **Plans are not concise** because each reply restates the whole quest list and notes. The prompt grows with history (1.6k to 10k chars), so replies grow too (1-4k chars).

## R3. The act menu relies on soft rules: flat, unranked, ambiguous, buried in stale context

- **Order:** options come in a fixed order and are never ranked or merged by history (`world.py:781-787`, by design). Exits sort by screen row (`world.py:40`), so the door mat at the bottom is always last.
- **Labels:** two different wall tiles both read "approach possible exit door" (`world.py:573-586`). The model cannot tell them apart.
- **Failure:** a failure is only a note plus one sentence in `DECIDE_SYSTEM` (`act.py:52-55`). It was broken 14 times. At S70 the model picked option 1 ("tried 1×") over the untried door mat at option 4.
- **Context:** much of the prompt does not bear on the choice. "Other open quests" is uncapped (`notebook.py:491-492`). Log entries are not truncated, so the whole 40-step intro text (~1.1k chars) rides along on every step. Stale beliefs stay in ("GAME FREAK is a clue").
- **Dialogue rule:** the decide path lost the "on a dialogue screen use advance" line that the free path has (`act.py:18`). That explains the button presses in the text box at S36-38.

## R4. Feedback is slow or noisy

- **No replan on repeated failure:** `same_action` and `no_change` emit no event (`tasks.py:53-57`, `loop.py:564-569`). GP added a "new failure → replan" trigger on 10-13; QS removed it on 10-15 (`266681e`) because the planner was micro-managing. So S64-75 and S77-98 ran on a stale plan, and the 20-step no-progress trigger only fired at S98.
- **Explore walks one tile:** `_unexplored` (`loop.py:439-452`) walks to the nearest frontier plus one step. 21 of 23 explore picks pressed once, and each one cost a ~4.5k-char act call plus perception.
- **Verdict noise:** a blocked move with any entity appearing or disappearing counts as `surprise`, not `miss` (`predict.py:79-81`). Outdoors the entity count swings 7-22 per frame (R1), so failures don't read as failures (23 surprises). Meanwhile 68 "hits" include the pointless object visits: a hit means "the predicted effect happened", not "this helped".
- **Wall exits are never refuted:** `_failed_exit` needs a floor tile at the exit's own tile (`world.py:198-204`). Refuted relations were written (r_relation_43-57) but nothing reads them.
- **Phantom exit:** the tile where the agent arrived counts as exit evidence (`world.py:536, 554`). That produced a phantom "exit door → room (used 1×)" on house 1F.
- **Not confirmed:** why "exit: north" in Pallet failed at the crossing stage (S100, S103). 11 of 30 outdoor steps never settled.

## R5. Perception drift (expected, and should be absorbed rather than tuned away)

- The same wall tiles were "window" at S65 and "door" at S66. Mom was "character", then "player" in dialogue frames, then "person". Names carry numbering ("fence post 1..7").
- This is normal VLM behaviour. It only hurts because of R1. Tuning prompts per label (window, rug) would be overfitting.

## Why fixes haven't stuck

- 113 commits since 10-10 over roughly 15 phases (GP, OM, OM2, OM3.x, OM4-A, T, HF1-5, IP, QS, QS-R, OT, live fixes) and 598 tests.
- The pattern: a live run shows a symptom, a phase adds a rule, flag or filter where the symptom appeared, dry gates pass on those frames, and the next live run fails somewhere else.
- Examples from this run:
  - The explore-quest filter was evaded in its first live run.
  - The failure-replan trigger was added, then removed two days later (an oscillation).
  - "Tried here" notes and the speaker binding both exist and work, but they are keyed on ids that churn (R1).
- Common factor: rules are being added downstream of an identity layer that isn't stable, so they multiply without closing the gap.
- Gates measure the patched symptom on fixed frames, and verdict "hit" measures local effect. Neither measures whether the run progressed.

## Guardrails against overfitting and the improvement loop

1. **No label- or game-specific logic.** No rules about "window", "rug", "next door" or "Oak". Every fix is stated in terms of tiles, ids, verdicts and quests.
2. **Upstream first, then re-measure.** Leave the planner and act prompts alone until R1 lands. Part of R2-R4 should fall out of it, and a run will show which parts.
3. **One fixed scorecard for every change,** scored from `truth.jsonl` (eval only, never fed to the agent):
   - ids per real NPC or object (target 1; Pallet NPC now 7)
   - failed-option re-picks while an untried option exists (now 14/99)
   - open quests the planner says it dropped (now 1)
   - steps from entering house 1F to reaching Pallet Town (now 21)
4. **One change, one live run.** If the scorecard doesn't move, revert instead of layering.
5. **Delete before adding.** Candidates:
   - the `_EXPLORE` word filter (evaded)
   - `self_spot` (constant 0.45, 0.451: no signal)
   - `Notebook._fit` and `Memory.view` (no runtime callers)
   - arrival-tile exit credit

## Proposed order (for approval; nothing built)

1. **R1 identity:** `(place, tile, kind)` becomes the key for static things and exits, and names become aliases. OT tracks already do this for moving actors. One place in `Memory.observe`. Expected to clear: NPC and object churn, door/window duplicates, lost talked-to binding, lost failure notes, part of the verdict noise.
2. **R2 quest writes:** an omitted or dropped quest either applies or comes back to the planner as an error. Reach checks use place ids. Replies become operations (add, close, drop) instead of restating the whole list, which makes them shorter.
3. **R3 menu presentation, not gates:**
   - Make labels distinguishable by position ("door, top wall, 1 up").
   - Gather options that failed here into one trailing row that stays pickable.
   - Cap the other quests and log lines.
   - Restore the dialogue line in `DECIDE_SYSTEM`.
4. **R4 feedback:**
   - A bounded replan when the focus action fails twice (once per intent, so the planner doesn't micro-manage again).
   - Explore walks until new cells are seen.
   - A blocked move is a `miss` whatever the entity churn.
   - Wall exits become refutable.
